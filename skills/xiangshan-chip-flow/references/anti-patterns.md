# 反模式：症状、根因、替代做法

> 这些都是“看起来在前进、实际在欠债”的模式。看到任意一条，先停下来补门禁，不要继续加功能。

## 1. 兼容性当正确性

**症状**：“游戏能跑/能开机，所以 CPU 对了。”
**根因**：把系统级冒烟当功能验证；没有指令级/总线级比对。
**替代**：Klaus/nestest/ISA 套件 + retire DiffTest；游戏只作为 L6 workload。
**证据**：`make difftest` 零差异；首个差异可复现。

## 2. REF 行为当硬件规范

**症状**：为了和 REF 对齐，改中断采样点/锁存逻辑，并把补丁写成通用语义。
**根因**：REF 可能有 bug，或与前端共享实现；没有独立校准。
**替代**：版本化 profile；规范/硬件捕获优先；共享实现标“非独立证据”；变更走 ADR。
**证据**：profile 版本 + 校准报告 + 外部测试。

## 3. harness 改写 reset 向量

**症状**：每个 testbench 自己 patch `$FFFC` 到测试入口。
**根因**：镜像不是自包含的；构建不产出入口。
**替代**：构建写向量；镜像原样加载；特殊入口用链接脚本/构建参数。
**证据**：同一镜像哈希在所有后端一致。

## 4. 镜像不可复现

**症状**：两次构建 SHA-256 不同；golden 哈希天天变。
**根因**：时间戳、随机数、未排序符号、绝对路径、并行顺序。
**替代**：确定性构建；双构建哈希进 CI；golden 带生成命令/输入哈希。
**证据**：CI 双构建 `sha256sum` 相同。

## 5. golden 一变就更新

**症状**：CI 红了，直接改 golden 哈希。
**根因**：把 golden 当“当前输出”，不是“已评审基准”。
**替代**：golden 变更单独评审；原因/影响/重跑证据；先定位回归。
**证据**：golden 变更 PR + 旧/新哈希 + 差异解释。

## 6. 删测试/弱化断言

**症状**：测试挡路，删掉/注释/放宽。
**根因**：把测试当障碍，不是资产。
**替代**：修实现；或明确标 known-fail + issue + 期限；删除需 ADR。
**证据**：测试数量/覆盖率不下降；known-fail 列表可追踪。

## 7. 永远成功的占位目标

**症状**：`make test` 永远 exit 0；`test-placeholder` 空实现。
**根因**：为了“CI 绿”造假门禁。
**替代**：失败必须非零；超时失败；空测试算失败；先写会红的测试。
**证据**：故意注入错误能让 CI 红。

## 8. 事后补周期

**症状**：DMA 固定加 513/514 周期；总线延迟用常量补偿。
**根因**：没有真实请求/仲裁/握手，用结果常量代替协议。
**替代**：请求/响应/仲裁/占用建模；513/514 只能当期望值。
**证据**：人工可核算的短波形；请求/响应守恒。

## 9. 只用 final-state 比对

**症状**：只比程序结束的 PC/寄存器；出错不知道第几条指令。
**根因**：没有 retire/bus trace。
**替代**：D1 retire → D2 bus → D3 device → D4 frame 逐层加。
**证据**：首个差异指令号 + 上下文。

## 10. 不可观测的接口

**症状**：设备内部状态只能靠猜；出问题加 `$display` 重跑。
**根因**：没有事件/trace 契约。
**替代**：每个外部接口有 `kind/tick/addr/data/we/source`；关键状态引到 `dbg_*`。
**证据**：失败报告能列出最近事件。

## 11. 电平当提交

**症状**：外设对保持多周期的 `we/addr` 重复写；寄存器被写多次。
**根因**：没有单点提交 `bus_strobe`。
**替代**：`bus_strobe = cpu_ce && bus_valid`；每个访问恰好一次；加断言。
**证据**：总线事务计数 == 指令访问数。

## 12. 隐藏回退

**症状**：timing 模式跑不动就静默退回 functional；为追平 REF 跳过事务。
**根因**：把“能跑完”当目标，不是“按协议跑”。
**替代**：禁止静默回退；失败显式报错；精度标签逐组件公布。
**证据**：日志/配置显示模式；无“补偿”代码路径。

## 13. 综合过 = 正确

**症状**：Yosys 跑通就宣布 RTL 完成。
**根因**：混淆“可综合”和“功能/时序正确”。
**替代**：综合后回跑同一套仿真/DiffTest；综合差异记录；时序/面积单独评审。
**证据**：综合前后门禁同一套通过。

## 14. generic cells 当面积

**症状**：拿 Yosys generic cells 当 FPGA LUT 或 ASIC µm²。
**根因**：不懂口径。
**替代**：标明口径；FPGA 看 LUT/FF/BRAM；ASIC 看标准单元 µm² + PnR。
**证据**：报告写清工具/库/corner/口径。

## 15. 先做后端再补验证

**症状**：RTL 还没 DiffTest，就开始跑综合/FPGA/PDK。
**根因**：后端可见、反馈快，容易上瘾。
**替代**：内环绿 → 中环绿 → 外环；外环失败先怀疑约束，不改 golden。
**证据**：S3/S4 门禁先过。

## 16. 墙钟 FPS 当性能

**症状**：用主机 FPS 证明芯片性能；不同机器数字打架。
**根因**：主机速度污染。
**替代**：确定性 tick/cycle 计数；请求/服务/等待/阻塞归因；manifest 固定主机信息。
**证据**：同配置同结果；优化前后事件流对比。

## 17. 宣称 cycle-exact

**症状**：README 写“cycle-accurate”，但 sprite evaluation/A12/DMA 是近似。
**根因**：没有逐组件精度标签。
**替代**：`functional/approximate_timing/calibrated_timing` 逐组件公布；未校准写限制。
**证据**：校准矩阵 + 未覆盖清单。

## 18. 宣称 tapeout-ready

**症状**：timing/DFT/DRC/LVS 没清就发“流片就绪”。
**根因**：把计划当成果。
**替代**：S6 逐项证据；checklist 评审；没有就写“prototype”。
**证据**：签核报告 + 评审记录。

## 19. 共享 REF/DUT 核心

**症状**：REF 和 DUT 共用 PPU/APU 代码，一致就宣布验证通过。
**根因**：省事；但一致可能只是同一 bug。
**替代**：独立实现；必须共享时标“非独立证据”；用外部测试/硬件捕获补独立证据。
**证据**：独立性说明 + 外部校准。

## 20. 范围蔓延

**症状**：v0 还没绿，就加 PAL、更多 mapper、更多外设。
**根因**：没有非目标/门禁。
**替代**：v0 范围冻结；新需求进 v1/backlog；每道门只做门内事。
**证据**：checklist 的 v0/非目标分明。

## 21. 一个人同时追五个环

**症状**：REF、RTL、CI、后端全由一人推，全部半成品。
**根因**：没有角色/优先级。
**替代**：先内环（REF+DiffTest），再中环（CI），外环排后；角色可兼任但独立性底线不能破。
**证据**：每周只有一个“当前门”。

## 22. 文档写目标当现状

**症状**：README 说“支持 X”，实际是 TODO。
**根因**：没有“最后验证日期/证据”。
**替代**：现状/目标分开；每条声明带命令/产物/限制；状态数字标日期。
**证据**：README 的 “What works today” 表 + 限制段。

## 快速自检（每次评审前）

```text
[ ] 有没有用“能跑”代替“对”？
[ ] 有没有改 golden/删测试？
[ ] 首个差异能复现吗？
[ ] 镜像两次构建一样吗？
[ ] 每个外部接口可观测吗？
[ ] 综合后回跑门禁了吗？
[ ] 精度标签写了吗？
[ ] 有没有“以后再补”的隐藏回退？
```
