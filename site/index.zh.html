04Parity

同一帧，两个世界。

一边是软件参考模型 NEMU，一边是 SystemVerilog RTL。拖动分割线——你看不出差别，这正是重点。

NEMU 是 REF，RTL 是 DUT。同一款 ROM、同一帧、同一个 256×240 NTSC 画面，RTL 输出的 SHA-256 与 NEMU 完全相同。这意味着从 CPU 取指到 PPU 出像素，这条链路上的状态对上了——至少在这一帧上。

参与前请先知道

  1. 改动 RTL 行为前，先加或更新测试。
  2. 提交 PR 前跑 cd rtl && make lint && make sim 与 DiffTest。
  3. 黄金哈希不随意改；要改必须有评审和记录。
  4. 不删测试来让改动“通过”。
  5. 不提交商业 ROM、BIOS 或专有 PDK 文件。

仓库根许可证尚未发布。在维护者发布许可与贡献条款前，请先不要贡献代码。ROM 许可证见 roms/LICENSES。

09FAQ

先把丑话说在前面。

这些是访客最常问的问题，答案尽量不修饰。更细的排查步骤在技术文档的“故障排查”一节。

能在浏览器里直接玩吗？
不能。当前 NEMU 是本地 SDL 窗口程序，RTL 通过 Verilator 抓帧，没有 WASM 或 Web 前端。这个网站负责讲清楚怎么在本地跑起来，不假装提供在线模拟器。
支持《超级马里奥兄弟》这类商业 ROM 吗？
仓库不附带、不提供下载。兼容性仍在推进，但目前不承诺任何商业 ROM 完整可玩。请只在合法持有的前提下使用自己 dump 的 ROM。
为什么还没有 FPGA bitstream？
全量综合、BRAM 映射、时序约束和板级 bring-up 都还没完成。当前 PPU 的 CHR/VRAM/OAM/调色板以触发器展开，直接上板不现实；先要把存储换成 BRAM，并把精灵扫描改成顺序扫描。
55nm 流片什么时候？
没有日期。它是长期目标，当前只是功能原型。路线图要求 FPGA 先验证，再谈时序、DFT、DRC/LVS 和 shuttle；现在连根许可证都还没发布。
我该从 NEMU 还是 RTL 开始看？
想玩、想验证行为，从 NEMU 开始；想做芯片，从 RTL 和 docs/open6502-chip/ 开始；只想快速跑一个 C 模型，可以看 GEM6502——但请注意它仍是遗留的指令驱动模型，不是完整的芯片时序平台。
许可证是什么？我能直接拿去用吗？
仓库根许可证尚未发布。六款 ROM 各自是 MIT，品牌资源在 docs/images/。在维护者发布根许可证与贡献条款前，请不要默认代码可以直接再分发；先读 CONTRIBUTING.md。
