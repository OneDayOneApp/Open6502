01Why 6502

一个故事，三个环。

香山官方把目标写成“探索高性能处理器的敏捷开发流程”：参考模型、差分验证、生成化描述、持续回归，再加上约半年的迭代与流片周期。6502 足够小，能让你一个人把整条链路走完。

内环 · 分钟 锁步 DiffTest：改一行 RTL，一条命令看到 PASS 或首个差异。这是香山方法论里最值钱、也最难自学的一块。 从差分验证开始 → 中环 · 每次提交 CI 回归、黄金哈希、确定性双跑、失败上传 trace。没有中环，内环只是脚本，不是门禁。 看验证体系 → 外环 · 每次迭代 综合、FPGA、开放 PDK 的 PPA 演练。不追 55nm，先把“从 RTL 到面积报告”的流程走通。 看外环门禁 →

0312 weeks

12 周，把分数练上去。

顺序按学习回报排：先把内环跑通，再补门禁，最后才碰生成化和后端。节奏是建议，不是承诺。

周做什么验收产出预估增益
1–2Difftest 补全：逐指令 retire（am6502 已覆盖平坦镜像）+ 总线/PPU 事务比对make difftest 一条命令，失败打印首个差异+2.5
3–4CI 补全：am6502.yml 已跑平坦/卡带/DiffTest；再加 lint、覆盖率与同种子双跑PR 不绿不能合，失败自动上传 trace+3.0
5–6检查点：任意周期 snapshot → restore → 继续锁步从第 N 周期复现同一分歧+2
7–9用 Chisel 重写一个模块（建议 ALU 或 PPU 子模块），与 SV 版本 co-sim两版等价 + 参数化 demo+7.5
10–11给 GEM6502 加计数器，做一次“改总线延迟 → cycles/阻塞”的实验一页可复现报告+1.5
12Yosys → OpenROAD/SKY130 跑一个小模块的 PPA一页面积/时序报告+2.1
目标12 周后把对齐分从 47 拉到 65–68≈ +19
不要跳步：先做 Chisel 再补 Difftest，会得到两个都不可信的实现；先做后端再补门禁，会把“能综合”误当成“正确”。内环没通之前，外环的每一分都不算数。
04What transfers

什么能带走，什么带不走。

6502 给的是流程肌肉，不是微架构品味。想清楚这一点，才不会在 NES 外设上越走越远。

能迁移到香山迁移不了
参考模型 + 差分验证的完整心智OoO、推测执行、分支预测
生成化 / 参数化的硬件构建方式Cache 一致性、多核、NoC
CI、回归、黄金哈希、确定性复现真实 PPA 优化经验（6502 太小）
检查点、回放、首个差异定位高性能微架构的设计品味
后端流程与流片门禁的检查单思维商业 PDK / DFT / 签核的工程强度

下一阶段：把载体换成 RISC-V 小核（果壳 NutShell 就是香山的前身），或者直接读香山的 Chisel 源码。6502 的任务是让你在换载体之前，已经把环跑短。
