00 · Overview

概览：这是什么，从哪里读起

这是一份“可以照着做”的文档：每条命令都在仓库里，每个结论都有测试或哈希对应。它也明确写清楚哪些事情还没做到——这不是一颗已经完成的芯片。

它是什么，不是什么

是：一个可运行的 NES 功能原型。NEMU 前端可以完整游玩 6 款 MIT 协议 ROM；RTL SoC 通过 28 项测试、Klaus 与帧级 DiffTest；代码可以综合，面积已逐模块估算。
不是：周期精确的 NES；不是已经有 bitstream 的 FPGA 工程；不是流片就绪的芯片；不是已有根许可证的开源项目。PPU 管线、DMC 仲裁、多游戏 lockstep DiffTest 都还没完成。

三条执行路径

NEMU / 6502EMU软件参考模型（REF）Playable游玩、黄金帧、CPU 参考行为
RTL SoC被测设计（DUT）Prototype综合、验证、DiffTest、未来 FPGA/ASIC
GEM6502C 功能 / 周期模型Legacy快速跑 PRG、指令级回归；不是完整时序平台

DUT 与 REF 必须独立。NEMU 不能被综合，RTL 也不能拿 NEMU 的实现来“对答案”。DiffTest 只比较可观测状态：寄存器、总线事务、帧哈希、音频样本、mapper 状态。

01 · Quickstart

快速开始：先让一帧跑起来

最短路径是 NEMU：编译一次，之后用 roms/play.sh 就能反复玩。想验证 RTL，则用 Verilator 跑同一款 ROM 并抓一帧 PPM。

编译并游玩 NEMU

shell
$ git clone https://github.com/OneDayOneApp/Open6502.git
$ cd Open6502
$ make -C NEMU m6502_defconfig
$ make -C NEMU -j8
$ ./roms/play.sh falling

也可以直接调用二进制：./NEMU/build/6502EMU roms/falling.nes。大多数游戏按 V 开始；1P 使用 WASD + Space/Z + X，2P 使用方向键与 , . / '。

shell

$ make

运行 RTL 游戏并抓帧

推荐直接使用仓库脚本，它封装了 iNES 提取、Verilator 构建和运行：

sim/game/run.sh 默认使用 macOS 的 clang++、SDK 与 Homebrew LLVM 的 libc++ 路径。Linux 或不同 LLVM 版本请通过环境变量覆盖：SDK=…、LIBCXX_DIR=…、CXX=…，或参考脚注调整链接参数。

03 · Architecture

系统架构：单时钟，多相位

所有时序逻辑跑在 21.477272 MHz 主时钟上，用 enable 相位产生 CPU、PPU、APU 与像素节拍，避免多时钟 CDC。复位异步拉低、同步释放。这是一个 NES/Famicom 兼容的数字 SoC，不是把 NES 主板逐器件复刻。

21.477272 MHz ──► clock / reset（÷12 CPU · ÷4 PPU · ÷24 音频） │ ┌─────────────┐ ┌───▼──────────┐ ┌──────────┐ ┌─────────┐ │ 6502 CPU │◄─►│ system bus │◄─►│ 2C02 PPU │──►│ video │ │ 2A03 profile│ │ decode / │ │ dot │ │ RGB444 │ └─────────────┘ │ arbitration │ └────┬─────┘ └─────────┘ └──┬───┬────┬──┘ │ ┌─────────▼┐ │ ▼ ▼ │ 2KB WRAM │ │ VRAM / OAM / palette └──────────┘ │ ┌──────▼─────┐ ┌──────────────┐ │ 2A03 APU │ │ cart / mapper│ │ 4ch + DMC │ │ PRG / CHR │ └──────┬─────┘ └──────┬───────┘ │ │ audio mixer cartridge bus

设计原则

  • RTL 是唯一可综合实现；NEMU 永不进入综合。
  • NEMU 是 REF，不是 DUT；两者不能共享同一个实现来“对答案”。
  • 先 CPU + 总线，再 PPU/APU，最后 mapper 与配件。
  • 先 FPGA 原型，再 ASIC；每级都有退出条件。
  • 每个外部接口都有可观测 trace，方便 DiffTest。

04 · CPU

CPU：先对功能，再对周期

open6502_cpu 是一个 2A03 配置的 6502 核。当前目标是把官方指令集与稳定的未文档化行为跑对，周期级总线行为仍在补齐。

已覆盖

  • 官方指令集，以及目标稳定的未文档化指令；十进制 ADC/SBC 已实现并进入 Klaus 覆盖。
  • 寻址：立即、零页、零页索引、绝对、绝对索引、间接、索引间接与分支。
  • 周期级总线动作：取指、操作数读、dummy read、RMW 双写、DMA stall。
  • 中断：NMI 边沿、IRQ 电平、APU frame IRQ、mapper IRQ；BRK/RTI 返回地址修正。
  • 累加器/内存移位、JSR/RTS、PHA/PLA/PHP/PLP、INC/DEC/BIT、JMP 间接、CMP/AND/ORA/EOR/ADC/SBC。

05 · PPU

PPU：能出画面，但还不是点级管线

PPU 是当前项目的面积大头，也是精度缺口最大的模块。它能渲染标题帧与游戏画面，但采用的是“逐点生成 + 扫描线末合成精灵”的结构，而不是真实 2C02 的 fetch/shift 管线。

CPU 写 $2006/$2007 │ ▼ VRAM / CHR / OAM / palette（寄存器阵列） │ ▼ 341 dots × 262 lines 点循环 │ ├─ 背景像素（名称表 + 图案表 + 属性 + 滚动） ├─ 精灵合成（优先级、sprite 0、8×16、overflow） ▼ 调色板索引 → RGB444 / PPM 抓帧

已实现

  • CPU 可见的 $2000–$2007 寄存器，$2007 自动递增。
  • CHR 8 KB、VRAM 2 KB、OAM 256 B、调色板 32 B 的内部存储。
  • 背景像素按点生成，支持 coarse/fine X/Y 滚动、名称表镜像。
  • 精灵叠加、优先级、sprite 0 hit、扫描线溢出、8×16 模式。
  • VBlank/NMI 与帧级输出；vid_rgb 使用 RGB444 调色板 LUT。

精度缺口

  • 没有完整的背景 fetch/shift 寄存器管线，渲染按点/扫描线组织。
  • 精灵评估是近似的，不是 2C02 的逐扫描线 OAM 扫描。
  • MMC3 A12 过滤与 IRQ 时序是近似实现。
  • PPU open bus、$2007 调色板读回等边界行为未完全覆盖。
  • 存储以触发器展开，直接导致 975,919 个通用单元；上板前必须换成 BRAM。

相关测试：ppu_tb、ppu_pixel_tb、ppu_sprite_tb、ppu_scroll_tb、ppu_overflow_tb。面积优化方向见 14 综合与面积。

06 · APU / DMC

APU 与 DMC：四个声道，一条未仲裁的总线

APU 已实现 2A03 的四个声道、帧序列器、长度/包络/sweep 与 $4015 状态，输出 16 位样本。DMC 有独立的采样与 DMA 请求逻辑，但总线仲裁仍是缺口。

输出路径

RTL 输出 aud_valid 与 16 位有符号 aud_sample；FPGA wrapper 提供 1-bit sigma-delta 音频接口。当前 RTL 没有桌面 SDL 前端，抓帧可以，实时听音仍要走 NEMU 或 GEM6502。

DMC 的未完成项

  • DMC 总线仲裁：与 CPU/PPU 争用时的优先级和插入时机未完全实现。
  • DMA 与 CPU stall 的精确周期对齐仍是近似。
  • DMC 采样地址/长度在跨页与循环边界的行为缺少硬件对齐。
音频目前是“功能可用”，不是“周期与混音精确”。在做 NEMU/RTL 音频 DiffTest 前，不应当用听觉主观判断“通过”。
07 · Bus / Memory

总线与存储：2 KB WRAM 和它的镜像

总线负责地址译码、片选与外设仲裁。它把 CPU 的读写分发到 WRAM、PPU、APU、DMA、手柄与卡带；每个外设都应有唯一、可观测的事务。

WRAM

$0000–$1FFF 是 2 KB 物理 WRAM，每 2 KB 镜像一次，共四次；$2000–$3FFF 是 PPU 的 8 字节镜像。open6502_wram 负责镜像解码，本身不做等待周期。

OAM DMA

写 $4014 触发 256 字节 OAM DMA：DMA 引擎从 CPU 地址空间搬运到 PPU OAM，并让 CPU stall。集成测试覆盖 $4014 触发、搬运内容与 stall 行为；精确的总线相位仍需继续对齐。

手柄

open6502_controller 实现标准手柄的串行移位：写 $4016 锁存，随后读 8 次得到 A/B/Select/Start/方向。两个端口独立。测试覆盖按键顺序与稳定位。

已知缺口

  • “每个外设都有唯一 bus transaction”还没有做到全覆盖。
  • OAM DMA 与 DMC DMA 同时请求时的优先级未验证。
  • CPU 访问 PPU 寄存器的精确时序（读写延迟、open bus）仍近似。
08 · Cartridge

卡带与 Mapper：0/1/2/3/4/7

RTL mapper 覆盖 NROM、MMC1、UxROM、CNROM、MMC3 与 AxROM。它处理 PRG/CHR bank、镜像、PRG RAM 和 IRQ；MMC3 的 A12 过滤仍是近似。

Mapper名称关键行为状态
0NROM固定 PRG/CHR，无 banking通过
1MMC1串行移位寄存器、PRG/CHR bank、镜像基础实现
2UxROMPRG bank 切换基础实现
3CNROMCHR bank 切换基础实现
4MMC3bank、PRG RAM、扫描线 IRQA12 近似
7AxROM32 KB PRG bank、单屏镜像基础实现

ROM 如何进入 RTL

  • NEMU 直接加载 iNES，支持 mapper 0/1/2/3/4/7。
  • RTL 仿真：sim/game/extract_ines.py 把 iNES 拆成 PRG/CHR 的 Verilog $readmemh 镜像。
  • FPGA（未来）：SPI Flash/SD 卡加载 iNES 到 SRAM/BRAM，或直接使用物理卡带连接器。
file-fixers.nes 与 stallar.nes 是 MMC3 回归的关键样本。它们能跑起来，不代表 A12/IRQ 时序精确。
09 · Video / Input

视频、输入与时钟：最后一段模拟边界

数字侧输出的是 341×262 NTSC 时序、RGB444 像素与 44.1 kHz 音频。模拟视频、模拟音频与真实手柄接口留给 FPGA 板级或外部 DAC。

项目当前实现说明
扫描时序341 dots × 262 linesvid_pclk / de / hsync / vsync
像素格式RGB444内部调色板索引经 LUT 转换
帧率NTSC 约 60 Hz仿真由帧循环驱动
音频16 位 PCM / σΔFPGA wrapper 提供 1-bit sigma-delta
输入两个标准手柄串行移位，joy1/joy2
FPGA 输出wrapper 存在无 bitstream、无上板验证

FPGA wrapper

fpga/open6502_fpga_top.sv 提供 VGA 与 sigma-delta 音频的顶层封装，但还没有完成全量综合、BRAM 推断、时序约束与板级 bring-up。Artix-7/Nexys A7 级别是规划目标，不是已验证结果。

时钟策略

不使用多个自由运行的时钟，而是单 clk_21m + enable。这样 CPU/PPU/APU 的相对相位在仿真和综合后都确定，也便于 DiffTest 以 tick 对齐。代价是所有逻辑都要遵守 enable 纪律；任何漏加 enable 的写操作都会在 12 个 21 MHz 周期里重复执行。

曾经的真实 bug：PPU 片选没有用 cpu_ce 限定，导致一次 CPU store 在 12 个主时钟上重复提交，$2006/$2007 写入错位。修复后标题帧才与 NEMU 一致。

发布门

11 · DiffTest

DiffTest：让两个实现互相作证

目标是在相同输入下比较 DUT（RTL）与 REF（NEMU）的可观测状态。比较粒度从指令、总线事务，到扫描线、帧哈希、音频样本与 mapper 状态。它不能证明 RTL 与真实 NES 一致，只能证明 RTL 与 REF 一致。

┌───────────────────┐ DPI / shared memory ┌───────────────────┐ │ Verilator RTL DUT │ ◄─────────────────────► │ NEMU NES REF │ │ open6502_top │ │ nes_ref_machine │ └─────────┬─────────┘ └─────────┬─────────┘ │ │ └────────────── DiffTest runner ───────────────┘ │ mismatch report

事件记录

systemverilog
typedef struct packed {
  logic        valid;
  logic [1:0]  kind;   // 0=cpu, 1=bus, 2=ppu, 3=apu
  logic [63:0] tick;
  logic [15:0] addr;
  logic [7:0]  data;
  logic        we;
  logic [7:0]  source;
} open6502_dbg_event;

同步点

模式与预算

  • cpu-only：先跑 Klaus/hello，零失配再谈其他。
  • frame-only：逐帧哈希，适合 NROM 游戏。
  • scanline：PPU 状态级，用于测试 ROM。
  • audio：逐样本或哈希容差。
  • full：总线 + PPU + APU + mapper。

性能预算：Verilator + REF 至少 106 cycles/s；遇到第一个失配就停，保留前后窗口。FPGA 只做帧/哈希级比较，点级比较留在仿真。

REF 独立性是当前风险：NEMU 前端与 REF 仍共享部分 PPU/APU 代码，REF 本身是暂定参考。必须继续用 Klaus、外部测试 ROM 与硬件抓取校准，否则 DiffTest 可能“一起错”。

13 · GEM6502

GEM6502：正在重写，不要高估它

GEM6502 的目标是 gem5 风格的事件驱动架构与芯片时序仿真平台：时钟域、资源争用、DMA 仲裁、检查点、因果统计，以及与 RTL 的独立校准。但当前实现仍是遗留的指令驱动功能/周期模型。

它现在能做它还不能做
加载 NROM PRG、跑指令并输出寄存器/周期统计没有已完成的时序 CPU、时序总线和校准过的芯片 profile
SDL 播放器、PPM 帧、MMC3 游戏回归事件队列尚未驱动正常执行；不是芯片级时序模型
与 NEMU trace 做回归对比不能作为硅前 signoff 或 RTL 时序替身
shell
$ cd GEM6502
$ make
$ make test
$ ./gem6502 run /tmp/gem-demo.bin 1000
$ ./gem6502 stats /tmp/gem-demo.bin
$ ./gem6502 play ../roms/stallar.nes

目标规范（中文）：requirements.md；架构与编码规则：coding-guide.md。这些文档描述的是目标能力，不是已实现功能。

14 · Synthesis

综合与面积：1.02M 个通用单元

使用 Yosys 0.60 做逐模块综合，流程为 read_verilog -sv -DSYNTHESIS → hierarchy → synth -flatten -noabc → stat。由于完整 PPU 组合渲染器对 ABC 映射过大，使用 -noabc，得到的是通用单元计数。

PPU 拆分

975,919 cells 84,224 flip-flops 840,701 muxes 40,283 AND 9,301 OR 674 XOR

大部分面积来自展开的 chr[8192]、vram[2048]、oam[256]、pal[32] 存储，以及逐像素/属性的 mux 树。FPGA 流程必须把它们映射到 BRAM，并减少组合精灵扫描。

必须一起读的 caveat

  1. 这是通用单元估算，不是布局布线后的面积。
  2. SYNTHESIS 跳过存储复位循环；仿真仍会初始化。
  3. SYNTHESIS 把 PPU 精灵扫描限制为 8 个以控制运行时间；仿真仍扫描全部 64 个。
  4. 顶层全展开综合在 600 秒内未完成，上表是逐模块求和，不是一次 flatten 的结果。
  5. 还没有时序收敛、LUT 映射、BRAM 映射或 ASIC 标准单元映射。

55nm 规划估算

方案裸片面积说明
当前 RTL，存储用触发器4–7 mm²不可接受
SRAM + PPU 重构1.2–2.0 mm²规划目标
推荐规划值~1.5 mm²用于成本模型

按 1.5–2.0 mm²、55nm 估算：量产后单颗成本约 USD 0.3–0.7（die + package + test），mask/NRE 约 USD 150k–400k+。这些是规划数字，不是报价。

15 · Tapeout

走向 55nm：四个门，逐级放行

路线图不是时间表，而是验收顺序：NEMU → RTL → FPGA → 55nm ASIC。后一级不允许掩盖前一级的失败；没有 FPGA 验证，就不该开始物理设计。

阶段目的当前状态退出条件
1. NEMU可玩的参考模型Working游戏可玩、Klaus PASS、黄金帧稳定
2. RTLSystemVerilog SoCFunctional prototype多游戏帧匹配、无未解释状态分叉、回归确定
3. FPGA真板子原型未开始bitstream 在板上跑游戏；视频/音频/输入稳定
4. ASIC55nm 流片规划时序/DFT/DRC/LVS clean；shuttle 与资金落实

RTL → FPGA 之前必须完成

  1. 为所有外设补齐 bus transaction strobe。
  2. 把 CPU 周期时序做到能通过 NMI/DMA 敏感游戏。
  3. 把 PPU 触发器存储替换为 BRAM 友好的数组。
  4. 把精灵选择改写为顺序扫描。
  5. 把背景渲染改写为 fetch/shift 管线。
  6. 完成 DMC 总线仲裁。
  7. 增加确定性帧序号 DiffTest。
  8. 完成全 SoC 综合与时序约束。

FPGA → ASIC 之前必须完成

  1. BRAM 换成 55nm SRAM macro。
  2. DFT/scan 插入与覆盖率目标。
  3. 时钟/复位/功耗意图。
  4. 用 55nm 标准单元库综合。
  5. 布局布线与时序收敛。
  6. DRC/LVS clean。
  7. 封装、pad ring、ESD。
  8. 落实 foundry shuttle 与资金。
不可协商：仓库不包含商业 ROM 或专有 PDK 数据；时序/DFT/DRC/LVS 未 clean 前不做流片宣传；黄金哈希变更必须评审；不通过删测试来让改动通过。
16 · Troubleshooting

故障排查：先对号入座

下面是最常见的几类问题。先确认你跑的是 NEMU、GEM6502 还是 RTL——它们的依赖和输出方式完全不同。

1. 找不到 SDL2，或编译时报 sdl2-config 缺失

NEMU 和 GEM6502 的播放器需要 SDL2。CLI 路径可以不要 SDL2，但 play、窗口与音频会缺失。

shell
$ brew install sdl2
# Debian/Ubuntu:
$ sudo apt install -y libsdl2-dev

如果装了仍找不到，确认 sdl2-config --cflags --libs 在 PATH 中；GEM6502 的 Makefile 通过它探测 SDL2，检测不到就会构建无 UI 版本。

2. Verilator 链接报 Undefined symbols ... __cxa_*

这是 macOS 上 Verilator 生成代码与 C++ 运行时链接不一致的已知问题。仓库脚本显式指定 clang++、macOS SDK 和 Homebrew LLVM 的 libc++ 路径。若你的 LLVM 版本不同，先找到实际路径再覆盖：

shell
$ ls /opt/homebrew/Cellar/llvm/*/lib/c++
$ LIBCXX_DIR=/opt/homebrew/Cellar/llvm/<version>/lib/c++ \
    ./sim/game/run.sh roms/falling.nes /tmp/falling-rtl.ppm

如果只是验证功能，可以先用 Icarus：cd rtl && make sim，它不依赖 Verilator 的 C++ 链接。

3. make sim 很慢、输出很长

它会依次编译并运行 28 个 testbench，本身就不是静默命令。先跑 make lint 排除语法问题，再重定向日志：make sim > /tmp/rtl-sim.log 2>&1，最后 grep -i fail /tmp/rtl-sim.log。

4. 游戏运行了，但停在标题画面

大多数 ROM 需要按 START，不是任意键。NEMU 默认 START 是 V，Select 是 C；GEM6502 播放器用 Enter / Backspace。确认窗口有焦点，并检查是否处于暂停（GEM6502 按 P 恢复）。

5. 没有声音

先确认没有传 --no-audio（无头截图命令会关闭音频）。GEM6502 需要 SDL2 音频设备；在 Linux 上检查 ALSA/PulseAudio。音频设备打开失败时，播放器会打印 SDL 错误并继续无音频运行，这是预期行为。

6. RTL 没有窗口、没有声音

RTL 是 SoC 仿真，不是桌面模拟器。当前通过 Verilator 抓 PPM 帧，没有 SDL 前端；音频只输出 16 位样本/σΔ 信号。想在桌面上玩，用 NEMU 或 GEM6502。

7. 自己算的 SHA 和文档不一致

先比较像素而不是 PPM 文件字节：PPM 头可能因工具不同而不同。把两张图都转成 PNG 后比较像素，或用项目自己的抓帧脚本生成。文档里的哈希来自仓库工具链，跨工具比较前先确认格式。

8. 缺少 Pillow，无法 PPM 转 PNG

macOS 可以直接用 sips -s format png /tmp/frame.ppm --out /tmp/frame.png；或者 python3 -m pip install Pillow。如果只是看 RTL 帧，用系统预览打开 PPM 也可以。

还是卡住？

提 issue 时请附上：操作系统与版本、命令原文、完整错误、clang --version / verilator --version、以及你跑的是哪条路径（NEMU / GEM6502 / RTL）。用 GitHub issue 或 PR 模板提交，信息越具体，越容易被复现。
