# GEM6502 芯片架构与时序仿真平台需求说明

版本：1.0（目标规范）；日期：2026-11-11。

本文规定目标和验收条件，不代表当前实现已经满足。配套实现规则见 [编码说明](coding-guide.md)。文中的“必须”为发布门禁，“应”为默认设计要求；任何例外必须有架构决策记录、适用配置、影响及验证证据。

## 1. 产品定位与目标边界

GEM6502 必须成为面向 6502/Open6502 SoC 的模块化、离散事件驱动、可配置、可校准的全系统架构及时序仿真平台。其核心能力对标 gem5：事件内核、SimObject 类组件、时钟域、端口与事务、功能/原子/时序访问、统计、检查点及可复现实验。

“芯片级仿真”在本项目中明确指：芯片架构与微架构层面的周期/事务时序建模，能够解释芯片各模块的时间关系、延迟、资源占用、仲裁和中断，并与规范、独立测试及 RTL 进行校准。计数正确、游戏可玩、截图一致均不能替代这项能力。

本项目不宣称执行 RTL、门级网表、电气、模拟、布局布线或制造签核仿真。相关验证由 RTL/EDA/实机路径承担。对于目标 SoC，不要求无关的多核、乱序 CPU、缓存一致性或操作系统生态；但不得以“6502 简单”为由省略时序端口、资源竞争和事件调度。

本规范选择独立的 C11 实现，要求对标 gem5 的建模能力，不要求兼容 gem5 的 C++/Python API、配置文件或检查点格式，也不将 GEM6502 冒充为 gem5 分支。若改用真实 gem5 承载，必须另立 ADR，评估 ISA、设备、构建和验证的迁移成本。

## 2. 必须回答的设计问题

平台必须能在不修改负载程序的情况下，通过配置变化回答：

1. 存储器延迟增加后，哪些访问被延迟，CPU 多等待多少时间？
2. CPU、OAM DMA、DMC DMA 竞争资源时，谁获得服务、谁等待、为什么？
3. 调整设备分频或相位后，MMIO、中断采样及数据返回发生在何时？
4. 更换总线仲裁、队列深度或存储器实现后，性能变化由哪些事件造成？
5. 与 RTL 的第一个行为/时序差异在哪里，能否从相同输入和检查点重现？

时序必须由资源与协议交互产生，不能仅从指令周期表、固定停顿常量或主机运行速度推导。

## 3. 当前基线与差距

| 项目 | 当前证据 | 迁移要求 |
| --- | --- | --- |
| CPU | `src/gem6502.c` 整条指令执行后累计周期 | 保留为功能基线，另建可等待响应的时序 CPU |
| 事件队列 | 有最小堆；`gem_step()` 不使用其驱动设备 | 重构为所有时序组件的唯一调度入口 |
| 总线 | `gem_bus_read/write()` 同步直接读写 | 替换为端口、事务、延迟和仲裁模型 |
| DMA | 立即复制 OAM，再增加 513 周期 | 变为真实发起请求并占用资源的总线主设备 |
| PPU/APU | 有功能模型、扫描绘制和音频输出 | 按独立时钟/事件接入；补足取数、DMA、IRQ 因果链 |
| 验证 | NEMU 指令/游戏 trace、画面及回放 | 保留；增加独立规范测试、事务比较和 RTL 校准 |
| 配置/恢复/统计 | 部分计数；无完整配置和检查点 | 新建配置、对象生命周期、序列化和统计体系 |

以上为代码审查基线，不用行数、游戏数量或虚构完成百分比衡量芯片仿真成熟度。现有界面、音频和游戏负载保留，但不是重构主线。

## 4. 仿真模式与模型配置

必须显式区分三种访问语义，不能通过 `side_effect` 布尔值冒充：

| 模式 | 目的 | 时序结论是否有效 |
| --- | --- | --- |
| functional | 加载、检查、功能执行及调试；不推进仿真时间 | 否 |
| atomic | 同步完成事务并返回估算延迟；不建模竞争 | 否，不得作为 timing 性能证据 |
| timing | 异步请求/响应，建模排队、资源占用和阻塞 | 仅在该配置已校准的范围内有效 |

访问模式与 CPU 模型分别配置。第一阶段必须提供功能 CPU 和 timing CPU；不强制先实现 atomic CPU。整机执行模式切换只允许在声明且验证过的 drain/同步边界进行，不允许存在未完成事务时直接切换。

至少定义两个独立模型配置：

- `nes_2a03_ntsc`：NES CPU/PPU/APU、mapper 与电气可见行为的规范配置。
- `open6502_soc_v1`：针对冻结后的目标 RTL 接口及硬件能力的配置。

十进制运算、非法指令、复位、RDY/等待、总线读写相位、IRQ/NMI 采样及存储器等待规则必须属于配置契约。两种配置不能因为暂时实现相似而混用。目标 RTL 规格尚未冻结的部分必须明确标为未校准。

## 5. 功能与架构需求

| 编号 | 必须具备的能力 | 可观察验收条件 |
| --- | --- | --- |
| R01 | 全局离散事件内核 | 正常 timing 运行全部由内核调度；无时间回退；同时间事件顺序确定 |
| R02 | 独立时钟域和复位相位 | CPU/PPU/APU 可独立配置合法分频与相位；停顿 CPU 不停止其他域 |
| R03 | 组件化对象模型 | 有名称、稳定 ID、参数、端口、生命周期、复位、统计、保存/恢复接口 |
| R04 | 时序端口与事务协议 | 接受/拒绝、重试、完成、响应背压均有明确契约；数据不丢失、不重复 |
| R05 | 地址路由与存储器 | 地址范围、镜像、ROM/RAM 权限、MMIO 和延迟可配置；冲突配置启动即报错 |
| R06 | 6502 timing CPU | 逐总线周期/微操作执行；等待响应期间不提前提交；覆盖配置规定的指令和可见总线行为 |
| R07 | 总线资源与 DMA | CPU/OAM/DMC 为独立请求方；按配置仲裁；停顿来自实际占用和握手 |
| R08 | 中断控制与采样 | IRQ 电平、NMI 边沿、屏蔽、确认及采样相位按配置实现；有完整来源链 |
| R09 | PPU/mapper 时序 | 取数地址、读写、滚动重装、可见像素、A12 和 IRQ 有统一时间戳；MMC3 IRQ 从实际 PPU 地址事件派生 |
| R10 | APU/DMC 时序 | 唯一 frame sequencer 驱动声道与 IRQ；DMC 通过总线请求取样并参与仲裁 |
| R11 | 可复现实验配置 | 同一配置/ROM/输入/版本复现相同事件与状态；错误配置不能静默回退 |
| R12 | 因果统计 | 能报告每个主设备的请求、服务、等待、阻塞原因、利用率和延迟分布 |
| R13 | 检查点与恢复 | 保存全部模型状态、时间、外部输入位置和待调度状态；恢复后事件及结果一致 |
| R14 | 分层 DiffTest | 支持指令、总线、扫描线、帧、音频及 mapper 比较；报告首个差异和前置事件 |
| R15 | 独立校准 | 每项精度声明有规范/独立测试/RTL 或实机证据；复制代码的两模型一致不能作为唯一证据 |
| R16 | 主机界面解耦 | SDL/音频输出不决定仿真时间，不直接修改硬件内部状态；输入变为有时间戳的事件 |
| R17 | 生命周期与多实例隔离 | 多个实例、复位、重新加载均无共享隐含状态；不遗留旧事件和旧事务 |
| R18 | 交付与可审计性 | 输出版本化配置、事件 schema、统计、校准报告和已知限制；每项门禁可运行复现 |

### 5.1 CPU 完整性要求

R06 的范围必须包括取指、操作数访问、跨页、分支、dummy read、RMW 的可见读写序列、栈、复位和中断序列。正式 timing CPU 发布前，不允许将未实现指令转交功能 CPU 并补周期。

允许开发阶段只支持少量指令，但必须以“实验模型”标记，对未支持操作立即给出可诊断错误。默认 NES 配置不得启用 NMOS 十进制计算。非法指令的支持集必须显式列出。

### 5.2 DMA 与中断完整性要求

OAM DMA 的对齐、逐次读写和实际占用，DMC DMA 的请求时机及仲裁，均必须有独立测试。固定增加 513/514 或其他周期只能用作期望值，不能替代实现。

IRQ/NMI 行为由选定芯片规范定义。为匹配 NEMU 而锁存 IRQ、移动采样点等改动必须重新经过硬件语义审查，不能直接作为 timing 规范继承。

### 5.3 PPU/APU 精度要求

逐像素输出不足以证明逐总线周期精确。必须验证取数与寄存器访问时刻、sprite evaluation、PPU 地址线活动、MMC3 A12 过滤，以及 APU/DMC 的总线/IRQ 相互作用。

精度标签必须逐组件公布：`functional`、`approximate_timing`、`calibrated_timing`。未校准组件参与的结论必须显示适用限制，不能统一宣称整机 cycle-exact。

## 6. 数据、观测与实验交付

每次实验必须输出 manifest，至少包含：构建标识或源码内容摘要、配置全文及摘要、芯片配置、模型精度标签、ROM 摘要、输入摘要、随机种子、检查点版本和起点、结束原因。缺少 Git 元数据时仍必须生成可复现的构建标识。

事件记录至少覆盖：`tick/delta/phase/sequence`、对象 ID、请求 ID、主设备、地址、操作、数据、因果父 ID、仲裁结果及 IRQ 来源。内部微操作、MMIO 和指令提交必须能关联到同一条指令。

必须同时保存确定性的仿真统计和独立的主机吞吐统计。不得用墙钟 FPS 代表芯片性能，不得把不同资源的重叠等待时间直接相加当成总执行时间。

检查点不得保存原始函数指针、文件指针、SDL 对象或主机地址。恢复失败、配置不兼容、缺失组件必须显式报错。

## 7. 验证策略与硬性门禁

下列门禁按依赖顺序通过。测试名称是目标交付接口，目前未实现的目标不得在文档或 CI 中显示为已通过。

| 门禁 | 对应需求 | 必须提交的证据 |
| --- | --- | --- |
| G0：规格冻结 | R03/R05/R08/R11/R15/R18 | 两个芯片配置的地址图、相位、等待、IRQ/DMA 契约及当前差距表 |
| G1：事件内核 | R01/R02/R03/R17 | 同 tick 确定性、取消/重排、复位隔离、多时钟、事件时间单调、零延迟循环检测 |
| G2：时序互连 | R04/R05/R07/R12 | 请求/响应背压、重试、公平性、队列饱和、延迟变化与事务守恒测试 |
| G3：时序 CPU | R06/R08 | 指令功能测试及可见总线序列测试；等待/中断采样；功能和 timing CPU 的架构状态对照 |
| G4：SoC 交互 | R07/R08/R09/R10 | CPU/OAM/DMC 竞争；PPU fetch/A12；frame sequencer/IRQ；规定场景与 RTL 对齐 |
| G5：实验工程 | R11/R12/R13/R14/R16 | 确定性回放、drain、检查点恢复、首差异报告、参数实验与统计一致性 |
| G6：校准发布 | R14/R15/R18 | 独立测试清单及结果、RTL 校准矩阵、六款负载回归、精度和性能报告 |

G0–G6 全部满足，才可发布“Open6502 芯片架构与时序仿真平台”。单个 profile 通过不代表其他 profile 通过；硬件校准范围不足时必须标明具体范围，不能宣称已完成全面实机验证。

### 7.1 必须包含的可计算实验

- T01：无竞争的已知请求序列，响应延迟由配置 1 改为 3 个服务周期，逐事务完成时间严格符合协议；CPU 周期变化按其实际访问与等待规则解析计算。
- T02：CPU 等待存储器期间，PPU/定时器仍按各自时钟产生预期事件。
- T03：OAM 与 DMC 竞争，仲裁获胜、等待及读写结果与人工可核算的短波形一致。
- T04：IRQ/NMI 在采样点前后分别到达，接受时刻与压栈序列符合 profile。
- T05：跨页、dummy access、RMW 对 MMIO 的副作用和总线序列符合规范。
- T06：同一 workload 改变合法的仲裁/延迟参数后，功能结果符合测试预期，时间和竞争统计按模型改变；对时间敏感的游戏不强求最终画面不变。
- T07：保存并恢复后，后续规范化事件流、状态、帧和规定音频结果与连续运行一致。
- T08：注入明确的总线/IRQ/像素错误，比较器必须在预期第一个同步点失败；空 trace、截断 trace、长度不等均失败。
- T09：同种子重复运行、多实例并行运行、复位再运行，得到相同的模型结果；主机显示帧率变化不能改变结果。
- T10：PPU 中途切换滚动、CHR、调色板，输出与扫描状态及取数事件一致；不能只比最终截图。

## 8. 范围与优先级

P0 是 G0–G3 所需的内核、端口、总线、CPU 与测试。P1 是 G4–G6 的系统集成、恢复、观测和校准。两者均属于最终目标的必须交付，不允许以阶段优先级为由永久删减。

新游戏、界面美化、更多控制器和高级音效均在上述主线之后。现有 SDL 界面仅作为模型观测器和输入适配器。无关的多核/O3/缓存体系不属于本次 Open6502 范围；未来扩展必须复用端口和事件基础设施。

不得给出未经实测的性能保证。G1 固定基准及主机信息，G3/G4 记录 ticks/s、CPU cycles/s、事件数、内存和 trace 开销；G6 必须公开可复现实测报告及相对基线退化解释，精度不得为追求吞吐被隐式降低。
