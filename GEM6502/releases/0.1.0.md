# GEM6502 v0.1.0 — legacy emulator baseline

Released: 2026-11-11. Tag: `gem6502-v0.1.0`.

This is the preserved instruction-driven 6502/NES emulator baseline before the
architecture/timing-platform redesign. It is not a calibrated chip timing
simulator, a gem5 fork, or an RTL/signoff model.

## Included

- 6502 functional execution with instruction cycle accounting.
- iNES loading and mapper 0/1/2/3/4/7 PRG support; bundled MMC3 CHR mapping.
- Scan-time raster framebuffer, scrolling, sprites and mapper IRQ compatibility.
- SDL2 player with movement, Space/Z jump, START, pause, reset and help.
- Pulse/triangle/noise/DMC PCM synthesis, SDL audio and mute control.
- Deterministic input replay and NEMU state/phase/frame regression.
- Target requirements and coding guide for the future timing platform.

## Validation

From the repository root:

```sh
make -C GEM6502 test test-ui difftest games mmc3
```

Release checks include unit/audio/UI tests, six directed CPU differential cases,
four NROM game smokes, both MMC3 title-state comparisons and 600-frame START
smokes. Stallar movement/jump replay compares framebuffer checkpoints through
1,200 frames and full CPU/cycle/PPU traces at frames 600 and 1,200.

The source archive contains `GEM6502/` and the bundled ROMs with their license
notices. Build/run from its root with `make -C GEM6502` and
`./GEM6502/gem6502 play roms/stallar.nes`. SDL2 is optional for the headless
build and required for `play`/`test-ui`. NEMU differential tests require a
separate built `NEMU/build/6502EMU` from the corresponding repository revision.

## Known limits and next version

Normal execution bypasses the event queue. CPU instructions complete before
PPU/APU advancement. Bus accesses are synchronous; DMA copies data immediately
and adds a fixed stall. IRQ behavior includes NEMU compatibility assumptions.
Neither hardware bus timing nor DMC arbitration is calibrated.

The next development version is `0.2.0-dev`. It starts with G0 profiles/contracts
and an experimental G1 event kernel. The legacy execution path remains available;
adding a new kernel does not itself complete G1 or enable a timing CPU. See
`GEM6502/docs/requirements.md` and `GEM6502/docs/coding-guide.md`.
